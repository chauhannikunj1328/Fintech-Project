## 1. Summary

[Brand] is a money app for everyday life with friends. Version 1 lets people **pay a friend, ask a friend for money, and track who has paid**, with a first simple way to **share a bill in a group**.

The aim for launch is to make paying and requesting between friends as easy as sending a message, without asking anyone for bank details.

## 2. Problem

People share costs constantly: dinners, rides, rent, trips. Today they:
- Keep a mental or notes-app tally.
- Ask for account details, then copy them between apps.
- Chase friends over chat, with no proof of who paid.
- Lose track once several people and several bills are involved.

Pain points to solve first:
1. Paying a friend takes too many steps if you do not have their bank details.
2. Asking for money feels awkward and has no status.
3. Group bills are done off-app, then settled one by one.

## 3. Goals and non-goals

### Goals (v1)
- A new user can send money to a friend within 2 minutes of finishing signup.
- A user can request money from anyone, including people not on [Brand], using a link.
- A user can see the status of every request and payment.
- A user can create a group and split one bill equally.

### Non-goals (v1)
- Chat or messaging between friends.
- Unequal splits (amount, percent, share).
- Automatic debt reduction across a group.
- Multi-currency groups.
- Investing, cards, perks, savings pots. These exist in the wider app but are out of scope here.

## 5. Scope

### In scope
1. Account and identity: phone signup, OTP, name, date of birth, address, email, passcode, ID and selfie check.
2. Contacts: import, search, invite, friend profile.
3. Send money to a friend or a bank recipient.
4. Request money via a payment link.
5. Scheduled and recurring payments.
6. Transaction history with filters.
7. Groups (basic): create, add members, split one transaction equally. *(designed)*
8. Notifications for payment and request events.
9. Support: in-app help and chat.

### Out of scope
See non-goals.

## 6. User stories

- As a user, I can search my friends by name, handle or phone and pay one of them in under five taps.
- As a user, I can add a note to a payment so my friend knows what it is for.
- As a user, I can create a payment link for an amount and share it through any app.
- As a user, I can see whether a link is created, paid or received.
- As a user, I can schedule a payment for later or repeat it monthly.
- As a user, I can invite a friend who is not on [Brand].
- As a user, I can create a group, add members and split a bill equally. *(designed)*
- As a user, I can see how much I have sent to and received from each friend.

### 7.2 Contacts and friends
| ID | Requirement |
|---|---|
| F-201 | A "Who to pay" list with search, alphabet index, and filters for Friends and Accounts. |
| F-202 | Invite a friend by link, message app or copy. |
| F-203 | Add a contact by name and phone or email. |
| F-204 | Friend profile shows total sent, account details, scheduled transfers and transactions. |
| F-205 | A label can be added to a friend (for example "Landlord"). |

### 7.3 Send money
| ID | Requirement |
|---|---|
| F-301 | Enter an amount with an on-screen calculator keyboard. |
| F-302 | Show fees before sending, including "No fees". |
| F-303 | Optional reference or note. |
| F-304 | Review screen with a warning: "Do you know and trust the payee?" |
| F-305 | Success state with a tracker: in review, leaving, arrived. |

### 7.4 Request via link
| ID | Requirement |
|---|---|
| F-401 | Create a link for a specific amount or any amount, with an optional note. |
| F-402 | Share the link through the system share sheet. |
| F-403 | The link expires after 9 days. Show the expiry. |
| F-404 | Tracker: Link created, Paid, Received in account. |

### 7.5 Scheduling
| ID | Requirement |
|---|---|
| F-501 | Choose a start date and repeat: never, daily, weekly, every 2 weeks, monthly. |
| F-502 | If the date is the 29th, 30th or 31st and missing in a month, pay on the last day. |
| F-503 | A list of upcoming payments with edit, deactivate and delete. |

### 7.6 Groups (basic) *(designed)*
| ID | Requirement |
|---|---|
| F-601 | Create a group with a name and members chosen from friends. |
| F-602 | Add one bill from a past transaction or enter an amount. |
| F-603 | Split equally among selected members. Any remainder is added to the payer's share. |
| F-604 | The group screen shows each member's balance (owes, owed, settled). |
| F-605 | A member can pay their share from the group screen. |
| F-606 | The organiser can send a reminder, up to once per day per member. |
| F-607 | Leaving a group is not allowed while the member has an open balance. |

### 7.7 History and notifications
| ID | Requirement |
|---|---|
| F-701 | Transaction list with Past and Upcoming tabs, search and an account filter. |
| F-702 | Push notification for: payment received, request paid, request expiring. |
| F-703 | Download a statement as PDF or Excel for a date range. |

## 8. Key flows

1. **Pay a friend:** Payments → choose friend → amount → note → review → send → tracker.
2. **Request with a link:** Payments → Request → amount → create link → share → status.
3. **Split a bill (basic):** Groups → create → add bill → choose members → equal split → members pay or are reminded.

## 9. Edge cases and states

| Situation | Behaviour |
|---|---|
| Wrong OTP | Error sheet, retry |
| Blurry document or dark selfie | Inline message, retake |
| Amount above balance | Red amount field, "exceeds balance", add money |
| Amount below minimum | Disabled button with message |
| Friend not on [Brand] | Offer invite and payment link |
| Link expired | Status "Expired", create a new one |
| Payment pending verification | Pending label and explanation |
| No connection | Blocking message, retry |
| Group member leaves with open balance | Blocked with explanation |

## 10. Success metrics

| Metric | Target for first 90 days |
|---|---|
| Signup to first payment sent | 40% within 7 days |
| Median time from signup to first payment | under 2 minutes of active use |
| Requests created per active user per month | 1.5 |
| Requests paid within 3 days | 60% |
| Groups created | 15% of active users |
| Payment error rate | below 2% |
| Support contacts per 1,000 payments | below 8 |

Targets are planning assumptions for the concept, not measured data.

## 11. Compliance and risk

- Identity checks and regulatory questions are required before the first payment.
- Show fees and exchange rates before confirmation.
- Fraud: show a trust warning on payments to new recipients. Limit new-account amounts.
- Data: keep records as required by law even after account closure, and say so at closure.
- Risk: users may expect chat and unequal splits at launch. Mitigation: set expectations in onboarding and gather feedback in-app.
